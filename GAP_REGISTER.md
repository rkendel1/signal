# Gap register

What Signal does not do, or does only partly, with the evidence. Rewritten for the rebuild (2026-11); earlier entries
that described removed modules (monitors, discovery, datasets, the Ghostpost codec) were retired with those modules
and remain in git history (`cbeacff`). Severity is for the product described in README.md.

## Platform gaps (FeltKit / FeltDB)

| ID | Gap | Severity | Evidence | What Signal does / proposed resolution |
|---|---|---|---|---|
| G-PLAT-1 | **No scheduled outbound fetch.** Job handlers are mutations, and mutations may not do network I/O, so a schedule cannot refresh an HTTP source. Since Phase 2 the extension's scheduler refreshes due feeds every minute *while a browser with the extension runs*; nothing refreshes otherwise | **High** for polled sources | `@feltdb/feltkit` skills/feltkit-services (handlers → mutations), feltkit-build ("never call fetch from a mutation") | `sources:refresh` is an action, run on request ("Refresh now") or by an external caller. Push and capture are evaluated on arrival. Signal does not ship its own scheduler. Upstream: let a job target an action |
| G-PLAT-2 | **AppBoundry artifacts have no network**; `sources:refresh` cannot run in one | Medium | AppBoundry manifest | Deploy on a FeltKit server |
| G-PLAT-3 | **No free-form JSON field type.** Attributes, mappings and explanations are canonical JSON strings, not queryable by inner field | Medium | `@appport/schema` builders | Acceptable while evaluation runs in Signal's code. It is why attribute queries load records and filter in memory (see G-SCALE-1) |
| G-PLAT-5 | **Prefix reads on composite indexes were incomplete past 1,000 records (FeltDB 0.21).** An equality read on the prefix of a composite unique index (`signal_links` by `sourceId`, index `[sourceId, recordKey]`) returned 1,000 of 2,000 records — `find` and `count` alike, silently — once another source's links existed. A similar read on `signal_observations` failed with "FeltDB returned the same cursor twice". Found by `scripts/measure.ts` at 2,000 records (a duplicate-link insert) | **High** (silent data loss in reads) | `scripts/repro-unique-prefix.ts` (remove the `[sourceId]` index on `signal_links` to reproduce) | **Worked around:** every potentially large equality read has an index on exactly its fields (`feltkit/app.ts` index note). Report upstream with the reproduction |
| G-PLAT-6 | **One transaction per ingestion; every read is fenced and re-checked at commit.** Bulk work (initial import, full re-evaluation) grows faster than linearly with many small reads; a single large source refresh is one large transaction. FeltKit also limits a request body to 2 MiB and a file to 1 MiB (gzip) | Medium | `docs/measurements.json`; before bulk preloading, a 2,000-record full re-evaluation took 89 s | Bulk preloading (`EvidenceLoader`) cut reads to a few per pass. Beyond a few thousand records per source, ingestion should be chunked into several transactions with an explicit "ingestion in progress" state — not built |
| G-TEN-1 | **Single tenant.** Records are owner-scoped; no organization sharing of sources or criteria | Medium | `feltkit/app.ts` authorize hook | FeltKit `auth.tenant` and shared ownership |

## Product gaps

| ID | Gap | Severity | Evidence | Proposed resolution |
|---|---|---|---|---|
| G-VAL-1 | **No real-world validation.** Every end-to-end result is on synthetic data (the example workspace, test fixtures). Identity thresholds (30 m, 250 m) and the address normalizer are unmeasured on real parcel and listing data | **High** for any accuracy claim | `tests/scenario.test.ts`, `lib/example.ts` | Run a real county parcel file plus listings captured in a person's own browser for the same area; measure false-match and missed-match rates before claiming accuracy |
| G-SRC-1 | **No credentialed sources and no database sources.** HTTP sources must be public | High for many real integrations | `feltkit/sources.ts` (no credential field) | FeltKit credential custody (`credential-ref:`) injected in the refresh action; never stored in Signal. Databases via an integration/component with egress |
| G-SRC-2 | **No native application data.** The platform exposes no other application's records to Signal; "native" sources are only those produced in Signal (captures, manual records) | Medium | FeltKit has no cross-app data capability in 0.3.31 | An AppPort capability contract other apps can expose and Signal can consume as a source kind |
| G-SRC-3 | **Push sources cannot be re-mapped retroactively.** A new mapping applies to records pushed afterwards; earlier pushes are stored raw but not re-applied | Low | `sources:setMapping` | Re-apply every stored push in order, if needed |
| G-SRC-4 | **Records without a source key are keyed by position.** An edit to such a row looks like a removal plus an addition | Medium | coverage reports `positionalKeys` | Content fingerprints for positional records, behind explicit uncertainty |
| G-SRC-5 | **Source health is reported, not alerted.** An unavailable source marks its findings, but nobody is notified that the source failed | Low | `sources:recordFailure` | A notification on status change |
| G-CRIT-1 | **No natural-language drafting of criteria.** The structured editor and JSON are the only ways in | Low | – | An action using `ctx.model.generate` that proposes a `signal.criteria/v2` draft shown for review; never saved without the person, never used in evaluation |
| G-CRIT-2 | **Date comparisons are limited.** Dates are ISO strings; `lt/gt` compare numbers only; no "within N days of now" on an attribute | Medium | `lib/engine/evaluate.ts` predicate | A date operator family |
| G-CRIT-3 | **No relationship or pattern criteria across entities** (e.g. "three listings on one street dropped price this week") | Medium | criteria are per entity | A separate aggregate detection type, if real use needs it |
| G-ID-1 | **Identity is tuned for places.** Identifier, address and coordinates are the only automatic matching bases; name matching is deliberately absent. Other domains rely on shared identifiers or manual linking | Medium | `lib/engine/identity.ts` | Per-domain matching rules as data, with the same explicit statuses |
| G-ID-2 | **Ambiguity resolution is order-dependent in one case.** A second record from the same source matching an entity is reported ambiguous; if that source was ingested first, the two records become separate entities and the later source's record is the ambiguous one. Both are flagged; neither is merged | Low | `resolveIdentity` same-source rule | Acceptable (both outcomes are explicit) |
| G-UI-1 | **Map has no basemap.** It plots positions only; no tile provider is configured | Low | `src/views/findings.ts` | Add a tile provider when someone chooses one (licence, privacy) |
| G-UI-2 | **No saved views.** Filters live in the URL (shareable, bookmarkable) but are not stored as named views | Low | `#/findings?…` | Store named views if users need them |
| G-NOTIFY-1 | **Notifications go to their owner only**; no routing to other people, quiet hours or digests | Low | `feltkit/notices.ts` | Add when there is a team use case |
| G-NOTIFY-2 | **No delivery while the browser is closed.** Notices are durable and shown when the browser (extension) or the web app is next open; there is no e-mail, mobile push or Web Push channel in the platform for this app | **High** for time-critical findings | `extension/src/background.ts`; FeltKit 0.3.31 has Mailerport only for account e-mails | A server-side delivery channel (e-mail via a provider integration, or Web Push with a push service) fed from `signal_notices` |
| G-POLICY-1 | **Fair-housing policy is not decided.** A name deny-list and default exclusion of personal-data columns exist; they are not protection | Medium | FAIR_HOUSING_REVIEW.md §5 | A policy owner decides (allow-list is the only precise option) |

## Site intelligence and ambient (Phase 2)

| ID | Gap | Severity | Evidence | Proposed resolution |
|---|---|---|---|---|
| G-SITE-1 | **Real-estate sites are not analyzed or polled.** Zillow and Redfin disallow their listing APIs to automated agents in robots.txt (and Redfin rate-limited this environment). No real-estate adapter exists; real-estate use relies on page capture in the person's own browser | **High** for the real-estate scenario | `SITE_INTELLIGENCE.md` §1 | A licensed listing data provider (an API with terms that permit it), connected as an ordinary source |
| G-SITE-2 | **POST/GraphQL, WebSocket and SSE are not analyzed.** The collector re-issues GETs only; GraphQL endpoints are listed, not understood; push channels are reported `not_observable` | Medium | `lib/site/collect.ts` header | Request bodies would need intercepting `fetch`/`XMLHttpRequest` in the page (MAIN world) or `chrome.debugger`: more invasive, needs explicit opt-in per site. Not built |
| G-SITE-3 | **Pagination is understood, not traversed.** A connection acquires the one URL it was given; a partial feed stays partial (stated in its limitations) | Medium | `feltkit/sites.ts` connect | Traversal using the definition's pagination params, with a page budget and the same conditional requests |
| G-SITE-4 | **Contribution trust.** Any member's analysis can add `discovered` definitions; there is no reputation or abuse control. Mitigations: definitions contain no code, connecting is always explicit, only acquisitions verify, curators promote | Medium | `sites:analyze` | Contributor quotas, curator review queues, signed adapter releases |
| G-SITE-5 | **Context matching is by exact URL.** "About this page" means a record whose own URL, or capture page, equals the page's address (fragment and trailing slash ignored). Pages that show an entity under another URL shape are not matched | Medium | `feltkit/ambient.ts` | Use the definitions' page templates and relations to map page URLs to record identifiers |
| G-SITE-6 | **Area conditions.** Distance outside a polygon is an upper bound (to the nearest vertex). A change to the area record does not re-evaluate the criteria that use it until the next evaluation or a criteria save | Low | `lib/engine/evaluate.ts` `kmFromArea`; `loadAreas` | Exact point-to-segment distance; dependency tracking from area records to criteria |
| G-SITE-7 | **Browser acquisition is attested by the person's browser** (like G-SEC-1): Signal records the body the extension fetched (hash-checked), not independently fetched | Medium | `sources:recordFetch` | Inherent to session-bound data; recorded in each ingestion's provenance (`acquiredBy: browser`) |
| G-AMB-1 | **The overlay e2e uses an open shadow root** (real builds are closed) and pre-granted host access; the permission prompt and the real side panel are checked by hand | Low | `scripts/build-extension.ts`, `tests/e2e/ambient.e2e.ts` header | Manual check per release |
| G-AMB-2 | **Live overlay updates need the tab visible**: a hidden tab refreshes when it becomes visible. Updates reach the overlay through the worker's change-stream subscription, kept alive by the overlay's 20-second ping | Low | `extension/src/overlay.ts` | Acceptable |
| G-AMB-3 | **Chrome may delay alarms**; the measured change-to-finding time is bounded by the feed's own interval (USGS: 60 s) plus up to one scheduler period | Low | `docs/site-validation.json`, ambient e2e | Document per feed |

## Security and operations

| ID | Gap | Severity | Evidence | Proposed resolution |
|---|---|---|---|---|
| G-SEC-1 | **Caller-attested fetches.** `sources:recordFetch` accepts the body the caller's own `refresh` action fetched (hash-checked, not origin-attested). A member can fabricate content for their own sources; ownership confines the impact | Medium | `feltkit/sources.ts` | FeltKit marking calls made by an action, or signing in the action |
| G-SEC-2 | **DNS rebinding.** The guard resolves, then `fetch` resolves again | Medium | `lib/sources/net-guard.ts` header comment | Pin the resolved IP at connect time (undici dispatcher `connect.lookup`) or route through an egress proxy |
| G-EXT-1 | **The extension's permission prompt and side panel are not automated.** The e2e test pre-grants 127.0.0.1 and runs the panel as a tab | Medium | `tests/e2e/extension.e2e.ts` header | Manual check per release |
| G-EXT-3 | **OAuth sign-in does not return into the extension**; password and dev sign-in work | Medium | FeltKit EXTENSION-HOSTS.md X6 | `chrome.identity.launchWebAuthFlow` handoff |
| G-EXT-5 | **No store packaging**; loaded unpacked | Medium | – | Chrome Web Store or policy install |
| G-TEST-2 | **Browser e2e tests need the project's dev server stopped** (one dev server per project) | Low | `tests/e2e/harness.ts` | Run from a copy, or stop `npm run dev` |
| G-TEST-3 | **A timing guard in the page tests is load-sensitive.** `security: … bounded work` asserts < 20 s; it failed once (20.9 s) while other suites ran in parallel and passes alone | Low | `tests/lib/page.test.ts` | Measure CPU time instead of wall time |

## Page extraction (browser capture)

Carried over unchanged: the page extractor is retained as the capture adapter.

| ID | Gap | Severity | Evidence | Proposed resolution |
|---|---|---|---|---|
| G-PAGE-3 | **Heuristics are English-leaning:** labels, availability phrases, class hints, relative dates | Medium | `lib/page/vocab.ts`, `values.ts` | Add vocabulary rows per language (tables, not code) |
| G-PAGE-6 | **Identity stability depends on the key.** Locator-keyed entities get new ids when the DOM moves. M7 made this *explicit*: `identity.strength = positional`, and such entities are reported as `uncertain` rather than added/removed. It is still not *solved* for positional identities | Low | `tests/lib/identity.test.ts` | Content fingerprints for positional entities, behind the same uncertainty rules |
| G-PAGE-7 | **Partial structural coverage:** no shadow DOM in static HTML (cheerio sees none; the overlay does), no iframes, simple RDFa only (no `prefix`/CURIE expansion beyond stripping), no PDF/image/OCR content | Low | `lib/page/extract.ts` | Extend per need |
| G-PAGE-8 | **Revision depends on observation time for relative dates.** Pages showing "3 hours ago" get a new revision every observation, because the inferred absolute time changes | Low | `values.ts parseDate` | Exclude inferred relative values from the revision hash, or keep the raw string only |
| G-PAGE-9 | **The held-out set is consumed.** Fixes were informed by its failures, so the current held-out scores are not an unbiased estimate | Medium | PAGE_QUALITY.md §4 | A fresh held-out set, labelled and committed before evaluation, for each future quality claim. It should include non-English pages and real JSON-LD conflicts |
| G-PAGE-10 | **Cross-row records.** HN puts one story across two table rows with no shared container: story recall 0.75, attributes 0.6, relationships 0.5/0.4 | Low | `docs/page-quality.json` hn-item | A rule joining adjacent rows only when the second row has no record of its own and references the first (e.g. the same item id in links). Must not merge unrelated rows |
| G-PAGE-11 | **Sidebar facts are not linked to the main record.** PyPI "Meta" sections become separate records; the author relationship is missed (0/1). The sidebar is duplicated for desktop and mobile | Low | heldout-pypi | Attach section-level facts to the main record when the sections have no identity of their own; deduplicate identical hidden/visible duplicates |
| G-PAGE-12 | **A land-lot card is typed `Product`** (T2: price + image) | Low | `tests/fixtures/discovery`, DISCOVERY_MODEL.md §9 | A real-estate cue set (acres/lot size + address) mapping to `RealEstateListing`/`Landform` before T2. Needs real examples, not a guess |
| G-PAGE-13 | **Duplicate rows across tables.** The same buildings in several tables become distinct row entities (heldout-tallest: duplicate rate 0.76, entity precision 0.696) | Low | heldout-tallest | Keep them distinct (rows are real). Link rows with the same strong key across tables via `sameAs` when a link URL identifies the subject |
| G-PAGE-14 | **Wikipedia's Parsoid annotations consume the entity budget.** `typeof="mw:…"` RDFa (Transclusion, File, Entity, …) produces about 1,500 machinery entities on large articles, and heldout-tallest is truncated at 2,000 entities in every variant. The `<style>` part was fixed (248 entities); the rest remains | Medium | `/tmp` probe in this session; `stats.truncated` on heldout-tallest | Ignore RDFa types whose prefix is not a declared vocabulary. Must be checked against the quality floor |
| G-EXT-10 | **Listing cards on a real site were not recognised.** A real search page gave Event/Person/Place (from JSON-LD) rather than listings, so a watch built on that page targeted Events and never alerted on homes. **Generic fix made:** a synthetic card layout reproducing the likely causes failed the same way, and now passes (`tests/fixtures/pages/listing-cards.html`). The causes were beds/baths/area lists becoming separate `ListItem` records; quantities split across `<b>`/`<abbr>`; and `<address>` not naming a heading-less card. **Not verified on the real site**: its markup was never available to Signal | High | Capture screenshots in this session; the fixture test | Re-capture the real page to confirm. If it still fails, a sanitized card snapshot shared by the user becomes a structural fixture. Large result lists may be virtualized, so only rendered cards are seen (coverage reports the declared total vs examined) |
| G-EXT-11 | **Zillow's cards are still unconfirmed.** Redfin's search page yields 41 listings; Zillow's yielded none. Snapshots now follow rendered visibility (content marked `aria-hidden` but displayed is kept, which a controlled test shows was discarded before). Whether that was Zillow's cause is unknown | High | Captures in this session; `tests/e2e/snapshot.e2e.ts` visibility test | The panel's "Download what Signal read" gives the exact input; a sanitized structural fixture from it would settle it |
