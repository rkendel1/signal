# Ghostpost → Signal: Extraction Audit

Audited repository: `rkendel1/ghostpost` at commit `369220a` (2026-08-12, 137 commits).
Method: read the implementation, not the documents. Every claim below names a file. Where behaviour was in doubt it was **executed**; those results are marked ▶ and reproduced in [`ACCEPTANCE_REPORT.md`](ACCEPTANCE_REPORT.md).

Status vocabulary: **IMPLEMENTED** (executable code exists) · **TESTED** (meaningful tests exist and pass) · **PARTIAL** · **PLACEHOLDER** (interface/stub) · **DOCUMENTED** (only described) · **MISSING**.

## Headline findings

1. **Ghostpost has no working automated test suite.** `package.json` has no `test` script. The only Rust unit tests (`wasm/src/hidenly.rs:653-707`) **do not compile** (`expected &str, found String`, 3 errors ▶), and `wasm/tests/web.rs` imports a `wasm::greet` that does not exist. The root `test-*.js/html` files exercise *copies* of logic, not the shipped code. So nothing in Ghostpost is TESTED in the sense required here. The codec is IMPLEMENTED and works (▶ verified by execution), but it was unverified until this extraction.
2. **The codec is the real asset, and it works:** round-trips including Unicode and DEFLATE are correct (▶). It has five defects that matter for reuse, all demonstrated against the shipped `wasm/pkg/wasm_bg.wasm` (▶):
   - `decode()` on a *reference* payload returns control-character garbage (`"\u0002\u0000\u0006\u0000abc123…"`) instead of an error. It does not dispatch on the payload marker.
   - A single injected zero-width character silently decodes to a **wrong** payload (`"\u001d\r"`). There is no checksum and no strict framing.
   - Truncated secure-note and AI-prompt payloads **trap** (`RuntimeError: unreachable`, i.e. a Rust panic in WASM) instead of returning an error.
   - Length fields are cast `as u16`. A reference id or metadata field over 65,535 bytes is silently truncated, which corrupts the payload.
   - Secure-note "passwords" are embedded in clear inside the invisible payload. Anyone holding the text can read them.
3. **Invisible Unicode is obfuscation, not encryption.** Confidentiality exists only server-side: `src/lib/encryption.ts` (AES-256-GCM, scrypt-derived per-user key) protects *hosted* secrets, and `src/lib/secure-notes.ts` (Web Crypto AES-GCM) protects note bodies. Anything carried inline is readable by anyone with the decoder. Nothing provides integrity of the inline payload.
4. **The overlay-runtime package is an unfinished extraction.** `packages/overlay-runtime/overlay-core/stackliveRuntimeBridge.ts:96,120` is explicitly `TODO` for runtime loading and experience launch. More importantly, **experience resolution never decodes**: `adapter.ts` `extractExperienceId()` searches the *visible* text for `||ghostid:…||`. That marker only exists *inside* the encoded payload, so it never matches, and every "experience id" is a 32-bit hash of the page text (`exp_<hash>`). The same logic is duplicated in `browser-extension/scripts/content.js`.
5. **Alerting does not exist.** There is no criteria model, no subscription, no scheduler, no notification channel, no webhook and no dedup. A repository-wide search for `notif|webhook|cron|schedul` finds only UI strings and a Supabase realtime listener for limited reveals. Analytics (Redis counters and a Supabase `decode_events` table) records that *someone decoded a post*. That is not alerting.
6. **The detector is format-specific.** It hard-codes the 9 Ghostpost code points and reports at most one result per text (`scanForPatterns` returns `[result]`). It cannot see other invisible-text schemes such as Unicode tag characters.
7. **Two decoders exist and they disagree.** `static/ghostpost-reveal.user.js:1031-1280` (`decodeHiddenMessage` at :1111) re-implements decoding in JavaScript (with pako). It handles a *nested* reference (`[0x00][0x02][0x00]…`, "double-wrapped" hosted posts) and validates reference ids against `^[0-9A-Za-z]{1,20}$|uuid`. The WASM decoder does neither. Signal's strict decoder adopts the userscript's rule, so both behaviours are preserved.

## What was *not* verified

- Behaviour on live X.com, Facebook or LinkedIn. The DOM-splitting fixes described in `XCOM_*.md` and `FACEBOOK_FIX_SUMMARY.md` could not be reproduced without those sites. Signal's overlay uses a simpler block-level reconstruction that is tested on synthetic split nodes only.
- The Supabase migrations were read but not applied.
- The SvelteKit app was not built or run. It is out of scope (non-goals: composer, accounts, dashboard).

## Git history notes

- `319c016` (Dec 2025): "Add compression marker to fix X.com decoding issues". This is the origin of marker byte `0x00`/`0x01` and of the legacy unmarked path, which Signal preserves.
- `676df63` says "append invisible chars instead of splitting text" for Facebook. The current `wrap()` inserts mid-carrier, so this was later reverted. Both placements decode, because detection does not depend on position.
- `0096766`, `c3a0545` and `2b73686` (all 2026-08-11) added reference, AI and secure-note payloads in one day, with no tests. That is where all three panic paths came from.
